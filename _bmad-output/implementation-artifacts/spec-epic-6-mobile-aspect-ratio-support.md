<intent-contract>

## Intent

**Problem:** The Actuator portfolio renders correctly on desktop but lacks comprehensive mobile aspect-ratio handling (19:9 to 4:3, portrait and landscape) — viewport is not notch-safe, tabs disappear below 768px with no alternative, terminal/footer are fixed-height and overlap content, touch targets are below 48px, topology/SVG and detail panels are not thumb-friendly, env registry table overflows, and swagger form is obscured by the on-screen keyboard, leaving Lighthouse mobile, WCAG 2.1 AA, and NFR1 gates broken.

**Approach:** Add a responsive-first CSS foundation (viewport-fit, safe-area env variables, fluid clamp tokens, dvh units, container queries) and then adapt shell navigation to a bottom-sheet pattern, make terminal/footer dvh-aware with orientation-specific heights and safe-bottom padding, rework each feature panel for mobile bottom-sheet/touch-action patterns and adaptive layouts, and finally sweep for touch-target, fluid-typography, reduced-motion, and forced-colors compliance — all with hand-rolled CSS tokens, signals-first Angular v22 idioms, no router, no JS resize listeners, and no new JS bundles.

## Boundaries & Constraints

**Always:** Define every new responsive value as a CSS custom property in `src/styles.css` token section (AD-6); hand-rolled CSS only, no Tailwind/component library or JS resize listeners; keep components standalone, OnPush, signals-first, built-in control flow; keep `ClusterStateService` as single signals store for shared state and `SimulationEngine` as single writer for outage state; preserve viewport-fit=cover and base-href-safe asset references; respect existing status palette, monospace stack, and spacing token conventions.

**Block If:** A responsive requirement forces adding Angular Router, a JS-based resize/layout library, committing build artifacts, or changing deployment pipeline/base-href handling; or a detail panel requires a non-CSS dialog library that breaks the hand-rolled CSS constraint — halt and report.

**Never:** Add `RouterModule` or any router import (AD-2 holds); introduce NgRx/RxJS stores, component-local duplicates of shared outage/tab state, D3/Cytoscape or any graph library (AD-5), Tailwind/Bootstrap, server rendering, new viewport JS polling, content changes to `portfolio-data.json` outside the mobile seam, or hardcoded raw colors/spacing outside tokens inside components or SVG attributes.

</intent-contract>

## Design Notes

Bottom-sheet is the single mobile detail pattern — shared across topology node detail, career replica detail, env registry deep dive, and swagger response modal. Implement once in `src/styles.css` as `.bottom-sheet` base (max 60vh, drag handle, backdrop, `transform: translateY(100%) → 0`, `padding-bottom: var(--safe-bottom)`, focus trap styling) and extend per feature with scoped overrides rather than duplicating animation/backdrop logic per component. iOS auto-zoom guard requires textarea `font-size:16px` on ≤767px or a viewport that permits scaling — prefer font-size because it is token-explicit and does not weaken zoom accessibility.
